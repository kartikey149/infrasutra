1. Infrasutra Kya Hai Aur Kyun Banaya Gaya?

Infrasutra ek enterprise-grade AI infrastructure management aur schedule synchronization system hai. Iska core objective real-world site construction reality aur corporate office ke Primavera P6 / WBS Schedule ke beech ke multi-crore disconnect ko eliminate karna hai.

The Real-World Industry Problem (PS-122 Disconnect)

Heavy infrastructure projects (jaise Oil India ke crude oil pipeline expansions ya gas processing plants) me field supervisors trench aur site par hote hain. Wo complex desktop software nahi chalate; wo Hinglish me WhatsApp audio ya text bhejte hain. Dusri taraf, head office me planners Primavera P6 me 5,000+ line items manage karte hain. Field data ko schedule me reconcile hone me 15 se 30 din ka reporting lag lagta hai, jisse unrecorded micro-delays critical path pe cascade hokar crores ke budget overruns ban jate hain.

Relational Database Schema (3NF SQLite)

  • users: id (PK), name, email (UNIQUE), password_hash, role (supervisor/planner)
  • projects: id (PK: PRJ-01), name, location, budget, supervisor, progress, varianceDays
  • project_assignments: id (PK), user_id (FK), project_id (FK), role. (Guarantees isolation).
  • schedule_activities: activity_id (PK: PIP-1001), project_id (FK), activity_name, discipline, planned_start, planned_end, percent_complete, wbs_level, location_zone
  • pending_updates: id (PK), project_id, raw_input, extracted_task, confidence, status (pending/approved), submitted_by
  • notifications: id (PK), user_id (FK), project_id, message, notification_type, is_read (0/1), created_at

4. AI & Machine Learning Pipeline

1. Fine-Tuned LLaMA-3-8B LoRA Model (Hinglish Extractor)

  • Base Model: unsloth/llama-3-8b-Instruct-bnb-4bit
  • Dataset: 40,000 domain-specific Hinglish construction audio/text transcripts.
  • LoRA Configuration: Rank $r=8$, Alpha $lpha=16$, targeting q_proj, k_proj, v_proj, o_proj.
  • Hardware Efficiency: 4-bit NF4 double quantization + native BF16 on NVIDIA RTX 4050 (6GB VRAM).
  • Training Performance:
    • Initial Loss: 4.257 ➔ Final Loss: 0.1751 (-96% reduction)
    • Mean Token Accuracy: Jumped from 45.17% to 95.36%
    • Saved Model Size: 13.6 MB (adapter_model.safetensors)

2. Semantic Matching Engine & $\ge 90\%$ Auto-Push Gate

Extracted task ko pre-seeded schedule activities se match karne ke liye hybrid formula use hota hai: 

Fuzzy_Score = RapidFuzz.token_set_ratio(query, activity_name) / 100.0
Cosine_Score = CosineSimilarity(TFIDF(query), TFIDF(activity_name))
Final_Confidence = max(Fuzzy_Score, 0.4 * Cosine_Score + 0.6 * Fuzzy_Score)

Rule:
  If Confidence >= 0.90 (90%) ➔ Auto-Approved & Pushed to Database (status: 'approved')
  If Confidence <  0.90 (90%) ➔ Routed to Planner Review Queue (status: 'pending')

6. Judges Ke Top Trap Questions & Bulletproof Answers

Trap 1: "Tumhara project Jira ya Trello se alag kaise hai?"

Bulletproof Reply: "Sir, Jira software development ke liye bana hai jisme tickets aur sprint points hote hain. Construction me linear dependencies hoti hain—jab tak civil trench excavation nahi hogi, piping weld nahi ho sakti, aur welding ke baad 24 ghante ka NDT inspection zaroori hota hai. Jira me Hinglish voice understanding, Primavera P6 WBS linking, aur pipeline coordinates nahi hote. Infrasutra heavy engineering ke liye tailor-made hai."

Trap 2: "AI kahan hai? Kya tumne bas regex ya if-else lagaya hai?"

Bulletproof Reply: "Nahi sir. Hamare paas dual system hai. Hamne LLaMA-3-8B Instruct model ko 4-bit NF4 quantization me apne RTX 4050 GPU par 40,000 Hinglish construction rows par 8.5 ghante train kiya hai (LoRA adapters ke sath). Iska loss 0.17 par converge hua hai aur token accuracy 95.36% aayi hai. Regex sirf ek offline fallback hai agar kisi client ke server me GPU na ho."

Trap 3: "Agar supervisor assign karte waqt email fail ho gaya to?"

Bulletproof Reply: "Sir, hamara email dispatcher modular aur completely non-blocking hai. Database transaction pehle commit hoti hai, in-app notification pehle save hoti hai. Email service try...except ke andar isolated hai. Agar internet down ho ya SMTP block ho jaye, tab bhi supervisor successfully assigned rehta hai aur access mil jati hai."

Trap 4: "Agar do supervisors ek hi second me ek hi activity update karein?"

Bulletproof Reply: "Sir, field updates direct activities table ko overwrite nahi karte. Wo pehle pending_updates table me unique auto-incrementing ID aur server timestamp ke sath write hote hain. Isliye SQLite me koi race condition nahi hoti aur har ek worker ka audit trail safe rehta hai."

Trap 5: "Tumne SQLite kyun use kiya? Production me scale kaise karoge?"

Bulletproof Reply: "Sir, prototype evaluation me SQLite zero-configuration deployment deta hai jisse judges bina Postgres server install kiye 2 second me run kar sakein. Lekin hamara schema 3rd Normal Form (3NF) relational SQL hai. Production me migrate karne ke liye sirf connection string ko PostgreSQL + PgBouncer me switch karna hoga bina kisi business logic change ke."
